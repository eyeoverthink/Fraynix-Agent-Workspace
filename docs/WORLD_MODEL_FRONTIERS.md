## What is already present

The application has persistent authored entities and versions; native bodies, gravity/contact dynamics and bounded manipulation; camera/entity observations; a learned numerical ramp-transition model and prediction-error history; durable Java goals; actual browser/canvas effects; and versioned physical/data procedures with checks, recovery and retained evidence. Edition020 also turns original-source motion data into auditable normalized values, derived motion and quality flags without replacing the source.

The tested predictive domain is still a small structured ramp world with engineered physical context. The broader native renderer/physics capability does not automatically extend that learned predictor to arbitrary geometry, multi-body interaction, visual perception or real apparatus. The separately rejected recorded-world forecasting result remains rejected. Persistent native entity state also does not prove reliable object identity from a live camera.

Java is useful as the owner of durable state, validated actions, simulation, task scheduling and local numerical computation. Its presence alone establishes neither a universal world model nor an unlimited neural-compute capability. Existing CPU/GPU backend measurements, task evidence and declared limits remain the basis for capability claims.

## Proposed next spatial milestone

This is a proposed direction in response to the new research references, not an implemented edition021 promise. It adds a spatial ingestion/prediction track alongside the existing browser/creation-procedure roadmap.

1. **Define a local scene package.** Include units, coordinate frame, scale provenance, persistent object IDs, poses, geometry references, body type, declared/measured physical parameters and source/uncertainty labels. Reject unsupported fields and ambiguous scale rather than guessing them.
2. **Keep appearance and interaction representations explicit.** A photograph, splat or rendered surface can supply appearance. Native collision geometry, body ownership and physical parameters need their own validated records. Import/render success and physical-validation success are separate outcomes.
3. **Deliver one real interaction.** Load one bounded scene with a floor, obstacle and movable object. Observe identities/poses, issue an existing-style grab/move/release task, retain actual contact and motion evidence, and show measured before/after state in the current UI.
4. **Extend action-conditioned prediction on measured state.** Add relevant position/orientation, linear/angular velocity, action history and contact context only as supported by the selected task. Compare predicted and executed outcomes; expose uncertainty/domain rejection and retain a simple stronger controller baseline.
5. **Use native experience as a curriculum.** Vary geometry, mass/friction, contacts and disturbances in declared training cases. Freeze separate evaluation cases before fitting or tuning. Retain versioned experiences, candidate models, quantitative acceptance and rollback.
6. **Validate observations against the environment.** Test persistent IDs through occlusion, scale/coordinate consistency, collision/contact behavior and prediction under unfamiliar conditions. For real captures, record calibration and sensing error; do not infer physical accuracy from visual quality alone.

The intended proof is: import a source-qualified scene, identify an actual object, predict a bounded manipulation, execute it through native physics, compare the result, and retain a verified procedure that handles a changed condition. Specific metrics and thresholds should be declared before that implementation's evaluation. A broader camera-trained or generative world model is a further capability with its own data, compute and validation requirements.

The design can remain local-first and keep the existing app. A large pretrained video transformer is not required to implement persistent authored geometry, physics, deterministic observations, small learned transition models or reusable task execution. Reconstructing unknown real scenes and learning broad visual/physical generalization remain substantive engineering/research work.
