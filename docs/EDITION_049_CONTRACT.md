# Edition 049 · Replayable observation evidence

Build the recorded-stream part of the evidence bench before accessing hardware. Java owns validation, clock alignment, event interpretation and immutable storage. The desktop imports/exports JSON and displays the same replay in Java Brain. Hardware acquisition remains a separate, explicitly configured step after identifying the board and sensor.

The input is a bounded, versioned package with declared provenance (synthetic or recorded), a metre coordinate frame, a target label, calibrated source clocks and ordered events. Camera measurements, camera predictions, missing observations and beam states are distinct. Every source has two clock anchors and an explicit timing uncertainty. Replay refuses extrapolation beyond those anchors, clock resets, non-finite data and mismatched source/frame identities. A content hash detects changed retained bytes, not whether externally supplied measurements are truthful.

For a beam at a declared X coordinate, compare its transition into blocked state with camera crossing intervals. A camera interval is measured only when both consecutive samples are measured, sequence-contiguous and within the declared sample period tolerance. During occlusion, a nearby beam transition can support a crossing event, never object identity, continuous hidden position or a native world update. Multiple possible matches remain ambiguous. Display camera-only evidence, prediction-only evidence and independent beam evidence separately. A first blocked sample is a baseline, not an observed transition.

Acceptance is measured on frozen labelled synthetic recordings with an offset clock, visible crossing, occluded crossing, shifted witness, missing samples and reset/invalid input. Verify expected classifications, uncertainty intervals, no pairing across a camera gap, first-state handling and abstention under ambiguous alignment. Validate file import, pause/seek/play, export, duplicate import, process restart, tampered-store refusal and unchanged native world through the actual app. Prior editions remain immutable. No claim of live hardware calibration, physical accuracy, identity recognition or learning gain follows from these synthetic checks.

Limits are 1 MiB/package, 4 sources, 4,096 events, one hour/session and 16 retained recordings. No new external dependency, paid service, background capture or automatic device access. Save an edition README, actual screenshots, offline guide, source inventory, tests and handoff notes.
