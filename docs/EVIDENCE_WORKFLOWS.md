# Evidence workflows · edition026

The registered `evidence-workflow-v1` completes three existing Java goal families
in order: `motion-data-report-v1`, `world-reach-report-v1`, `creation-web-v1`.
It then independently audits the generated explorer. Enter through **Create &
verify → Run a complete evidence task**, or ask chat for an **evidence workflow**.
This is a bounded composition of registered procedures, not a general planner.

Java owns the parent, immutable intent, source binding, stage identity, checks,
recovery and skill promotion. Electron executes existing leased browser/model
effects. The selected installed local model writes the explorer; it cannot
declare its own rows or mark the audit passed. The renderer presents the existing
goal card, canvas and shared Skills library. No additional workspace page,
runtime dependency, cloud service or model weights are required.

## Source and execution

The parent freezes request/title/model, dataset/version/original and mapping
hashes, quality criteria, native parameters, target and disturbance. An optional
authored native scene is version/hash bound. Sources accept at most1000 normalized
observation rows and100K original CSV characters; no hidden subsampling occurs.

1. The actual motion-data goal reconstructs original observations and tests its
   report. Quality flags remain outcomes; they are not silently discarded.
2. The native world goal predicts, applies control, experiences a disturbance,
   verifies the endpoint and tests its real report. Its29 recorded forecast pairs
   remain native simulation evidence.
3. Java reconstructs a bundle: original CSV, combined `evidence.csv`, qualified
   metadata and index. Every source observation and actual native pair is retained.
4. The creation goal freezes14 real behavior checks before generation. The local
   model builds an interactive table/filter/reset and two native SVG traces.
5. A separate leased host observation reads actual DOM table cells and SVG point
   lists. Java compares them against its reconstructed bundle, including all
   string cells, order, visibility, point count and coordinate error.
6. Only the verified complete parent can retain a whole-workflow procedure.

The exact visible qualification is:

> Observation data and a separate native simulation. No physical calibration or causal equivalence is claimed.

Source video-derived centroids and frozen scale assumptions remain qualified
observations. The unchanged edition013 physical-calibration rejection and
edition024 tracking rejection are not superseded by content creation.

## Frozen graph contract

The native chart uses SVG viewBox `0 0 800 300`:

```text
yMax = max(1.8, targetM + 0.2)
svgX = 40 + 720 * timeSeconds / 1.5
svgY = 260 - 220 * positionMetres / yMax
```

Both native_actual and native_prediction contain all29 original pairs in order.
Maximum absolute coordinate error is0.02 SVG units. This contract was declared
before live generation. Checking coordinates is a numeric rendering-fidelity
check, not general visual recognition or validation against physical reality.

## Durability and authority

Parent records live in `workflows/tasks.fworld`; existing child goals and
procedures remain in their shared FactoryWorld checkpoint. Stage input is saved
before start. Child UUIDs derive from parent/stage identity. An interrupted start
reconciles its stable intent instead of creating another child. Verified completed
stages and original native run are reused after restart. An incomplete native
stage follows its explicit new-attempt recovery, preserving the earlier attempt.

One parent reserves the shared runner, including while interrupted. Manual scene,
source, artifact and runner mutations are rejected until Resume or Stop. Children
cannot be independently resumed, canceled or saved as detached skills. Internal
owned actions use registered handlers; source text never installs host code.

The supervisor acquires its own lock before the goal runner. HTTP goal-list
polling must not acquire the workflow lock while holding the goal lock. A live
test exposed that reverse acquisition; its first interrupted project/thread dumps
are retained and actual integration polls both lists concurrently.

Stop cancels owned work and revokes host claims. Stale/foreign/late receipts
cannot write a successful parent. Resume revalidates source, completed stage
artifacts, bundle and current child. User edits are preserved and rejected as
changed evidence. Private audit leases expire after30seconds and carry a nonce.

Budgets:20 parent records, three child goals per parent, three total creation
drafts including independent-audit repair, three explicit parent resumes and
1200seconds per attempt. Existing child budgets also apply. Failure is visible;
the runtime never lowers checks to make a draft pass.

## Retained skills and reuse

The shared Skills library stores a versioned procedure with prerequisites,
registered actions, recovery, source outcome and explicit defaults. Reuse binds
a fresh selected dataset/version and can change declared native conditions and
quality criteria. Counts and plot scale are reconstructed from the new evidence.
It runs a new task and verifies it; this is procedural retention, not LLM-weight
training or automatically learned physical dynamics.

Examples:

```text
Run an evidence workflow on the selected observations. Predict and reach the
target despite a disturbance, create an explorer and save as observed-evidence.

Reuse evidence workflow observed-evidence on the selected observations.
Use 30 degrees, friction 0.1 and target 1.8 metres. Set speed limit 0.4 m/s.
Keep quality flags and the source/simulation distinction visible.
```

Exports preserve original generated HTML/CSS/JS, injected source CSV/JSON, actual
canvas receipts, original observations, native run, parent/stage metadata and
audit. The offline documentation example changes only the local source-fetch
transport to embedded exact JSON and separately retains every original file.
Use the Java source/bundle/report as evidence; generated prose is presentation.
