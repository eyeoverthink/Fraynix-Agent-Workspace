## Change and authority

Java will estimate complete task cost from at least two distinct nearby tasks,
each with at least three distinct simple/memory comparisons. Group by task before
limiting neighbours, so repetitions cannot displace all task diversity. Weight
task means equally. The empirical half-width is the sum of: at least 500 ms or
the largest within-task simple range plus memory range; the largest task-mean
saving deviation; and twice the maximum scene distance times the largest cost.
This covers observed repeat variability without treating uncertainty of a mean
as uncertainty of the next task. It is not a calibrated probability guarantee.
An estimate may select memory only when its lower saving bound exceeds zero.

Exact implementation, runtime, receipt, workload, proof-state and distance gates
remain mandatory. Original native traces, outcomes, commits and calibration
files are checked as before. No duplicate goal can count twice. Unsupported
conditions remain simple control. New code identity requires fresh memories;
edition 083 evidence is preserved and never relabelled.

## Fixed collection and separate evaluation

Two independent projects learn fresh current-code procedures using the two
previously declared 083 calibration scenes. One is measured after restart without
saving; one after restart while saving a reusable skill. Experience retention is
explicitly disabled during timing, keeping the chosen receipt fixed while all
completed skills and verified world commits remain real. These timings do not
calibrate the distinct retain-experience workload. The app must refuse that
mismatch; calibration with an expanding bank remains a separate next experiment.

Per project: one learning goal; two nearby calibration scenes with three paired
repetitions each (12 goals); two untouched evaluation scenes with two repetitions
of simple, memory and calibrated control (12 goals). Total: 50 native goals.
Every measured goal starts a fresh Java owner. Method order is counterbalanced.
Evaluation uses separate exact copies of the closed prepared project. No result
may retune scenes, controllers, margin formula or acceptance checks. Failures are
retained and dependent collection stops for diagnosis.

Fixed budget: four logical processors, 768 MiB Java heap, actual Windows affinity,
D: storage. Only one native study runs at a time. Startup, learning, calibration,
original-evidence processing and reopen costs are reported separately. Cold
means a new owner, not an OS cache flush or an interrupted goal.

Compare the old 080 arithmetic and the new repeated estimate on the same fitted
original pairs, against held-out actual simple-minus-memory costs. Report support,
interval hits and width, point error, chosen policy, actual complete task times,
and costs of collecting calibration. A wider interval alone is not proof of a
better policy. No automatic promotion, new physics claim or model-weight claim.
