# Edition 182 implementation plan

The Workbench now registers two Fray browser tools. Java matches the requested direction, binds the review to its selected code and verifies each browser run before saving. The local classifier can handle a clear converter request from Chat with the model service disabled.

The Celsius recipe was compiled with the original FraynixBoot compiler from **celsius × 9 ÷ 5 + 32**. Its output has three constants and a 16-byte instruction stream. One bounded Java reader handles the instructions required by both recipes. The browser computes Fahrenheit with scaled integers. Comparing the two implementations exercises the offset, order of operations and negative values. [Original Fray compiler source](https://github.com/eyeoverthink/fraynixboot/blob/d93947154a1f21dcfd8dfcc97f27439fed6e3275/src/main/java/fraymus/lang/FrayBytecode.java)

The primary acceptance run uses 12 temperature cases. Eight additional cases exercise fresh inputs and sign changes. Reopening the previously saved inch tool compares its exact receipt with the original Edition 181 record. The new HTML must reopen after restart and convert a fresh value directly from disk. The Java gate must refuse a receipt or preview borrowed from the other tool.

A follow-up could use the same architecture for a reviewed request that combines two conversions. Validate each intermediate result and test two mistaken unit handoffs before treating it as a reusable procedure.
