# Edition 191 implementation and qualification

Use the existing Java Chat mission and native Game Lab scheduler. Bind the request to one imported Blender candidate by UUID. If the original lacks a completed attempt, run its bounded native playtest first. A passing original needs no repair. Recheck the failed trace, engine, candidate binding and terminal image.

The repair rule uses the final eight grounded samples and their position and speed. It looks for missing support immediately ahead at the same deck height. A single candidate can reposition at most eight existing raised tiles in that span. The repair uses the lowest available raised tile in each eligible column and requires a remaining unsupported span of at most two grid cells. Preserve the source layout, asset manifest and the other Blender edits.

Record the diagnosis before building the candidate. Allocate the derived candidate from the original chat ID so recovery after a write can reuse the same candidate. A resumed task rechecks its source and recorded decision before playtesting. Run two separate fresh native sessions. A successful report carries the failed trace, exact tile changes, both passing traces and the native image and engine hashes. Run the actual canvas checks on its title, outcome and evidence link before Chat reports verification.

Test a fresh wide-gap import without a preexisting baseline. Pause after the repair and restart the desktop. Resume the same Chat task and candidate, verify both native runs and open its report. Tamper with the original run's saved image and the report's stored browser receipt in the isolated project and confirm verification refuses both. Repeat the request without the optional pause. Confirm the original candidate file is byte-identical and both successful trace hashes agree.

## Reproduce locally

Set FRAYNIX_BLENDER to a local Blender executable and configure JDK 21. Choose a fresh output directory.

~~~powershell
.\gradlew.bat --offline :workspace-engine:installDist :prepareGameRuntime115
node docs/publication191/validate-desktop.cjs build/edition191-check
python docs/publication191/validate.py
~~~

The test loads the published wide-gap fixture by default. A second positional argument can specify the same fixture generated by the Edition 190 test.
