## Certificate authority and invalidation

The cached arm starts with an EMPTY study-local certificate store. Its first needed reconstruction executes natively and is fully charged to that task. Only a passed original at-rest reconstruction may create a certificate. Later hits re-read and hash the exact frozen episode and the original owned reconstruction trace, check native and certificate/verifier version identity, original plan/source, current restore eligibility, original WorldVerify gates and the unchanged073 sample/pose comparison. The certificate references an earlier `cached` reconstruction attempt in the SAME study, its original run/hash and checked native result. It cannot reference a forecast, actual task result, another study or an unfinished/failed run. An episode component, source/plan hash, engine, verifier, restore contract, certificate or original-proof mismatch invalidates reuse. Missing/invalid certificates retain the reason and require a fresh bounded reconstruction; incompatible owned episodes refuse at start/resume. Preserve invalid certificate bytes before replacement. Corruption detection is not security against a machine administrator rewriting every authority store.

Cached proof is NEVER a forecast or actual result for a changed scene. Each new task still requires its own native forecast and a distinct actual execution, original WorldVerify, >=95% sample coverage, <=0.01m position and <=0.5-degree forecast/actual residuals. Old reconstruction gates remain >=95%, <=0.00001m and <=0.001degree. No active-world write or new successful skill/memory is authorized by the study.
