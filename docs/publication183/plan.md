# Edition 183 implementation plan

Register a Workbench chain with a signed starting value and two ordered conversions. The first Fray program turns inches into millimetres. The second program divides the verified millimetres by ten. Java validates the unit agreement before the review is created.

1. Approve one chat request. Java binds its exact quantity and stage order to the reviewed HTML.
2. Exercise the first button in Chromium. Confirm the second button started disabled and its result is still waiting. Java compares the actual millimetres with the original Fray program and persists the observation before it releases the next steps.
3. Check the displayed intermediate again, exercise the second button, and compare the reported handoff and final centimetres against Java. Save the HTML only after those observations pass.
4. Reopen the original receipt and compare the two earlier converters with their saved proofs. Try fresh signed decimals, values near the range boundary, and edits that could otherwise leave stale intermediate values active. Check the single-file export offline.

The second program was compiled from **millimetres / 10** with the original FraynixBoot compiler. The browser calculates both steps independently with scaled integers. The chain carries five decimal places in millimetres and supports six in the centimetre result. [Fray compiler source](https://github.com/eyeoverthink/fraynixboot/blob/d93947154a1f21dcfd8dfcc97f27439fed6e3275/src/main/java/fraymus/lang/FrayBytecode.java)

The next acceptance test could introduce a second compatible chain and exercise alternate unit names, unsupported dimensions, and an interrupted handoff in a full desktop session.
