# Edition025 · the workflow becomes the content

User direction: retain the current integrated local application, acknowledge its
small-budget engineering context, and make the agent participate in creation and
verification inside the app. This is a continuation of [edition024](../README-024.md),
not a replacement interface or a claim of parity with general embodied agents.

## Implement now

Add `creation-web-v1` to the shared Java goal runner. Freeze the request, selected
local model, optional selected CSV source and observable behavior checks before
drafting. The existing canvas executes generated HTML/CSS/JS. Java owns artifact
identity, bounded revisions, test decisions, cancellation, explicit restart
recovery and retained procedural skills. The host supplies real model generation
and actual Chromium interactions through private leased effects.

The first proof creates an interactive explorer of the existing recorded tracking
trace:450 original prediction rows, profiles and real overlap values. Java copies
the chosen source unchanged into the new artifact and derives row-count checks
from its own CSV parser. The generated app can filter rows and reset the view.
Reuse must bind a different selected source and recompute its expected counts.
This makes the app's own activity usable content without manufacturing new data.

Fixed execution bounds: one active shared goal, at most3 drafts across recovery,
24 interaction/check steps,600seconds per attempt,3 explicit resumes and existing
artifact file/path budgets. No automatic tool installation, shell execution,
cloud provider, new model weights or online LLM training is introduced.

## Evidence required

- Actual locally generated interactive content, with frozen checks before code.
- Failed real browser checks drive a recorded bounded revision; failures remain.
- Restart between write/test and after a passing receipt does not duplicate work.
- Cancelled, forged, stale, source-changed and externally edited outcomes cannot
  complete or become saved procedures.
- Retained procedure reuses the workflow on a fresh source, with new checks and
  independent observed behavior rather than blind replay of a copied artifact.
- Existing physics, game, brain, world-model, data, perception, tracking and
  creation paths still pass appropriate regression and clean-checkout checks.
- Extensive README025, real screenshots, source inventory, offline guide, maps,
  current notes and a main/tag push verified directly from GitHub.

The controlled repair test may supply deliberately broken code; it must be
labelled as a software control. The separate live-model proof must use the real
installed local model and retain its actual output and browser receipts.

## Ordered next work

1. Connect complete creation tasks to the durable shared runner and saved skills.
2. Compose registered creation, data and physical procedures into longer goals,
   with explicit source bindings and separate task verifiers.
3. Improve physical/object observations on experienced failures, then freeze a
   new candidate before collecting different evaluation footage. Edition024's
   failed quality result and installed profile identities remain preserved.
4. Evaluate retained improvement on unfamiliar tasks and after restart, before
   promoting changes. Broader world models, physical calibration and neural/GPU
   compute need their own measured gates.

The strength to build on is locally owned state and a visible action/verification
loop. General competence, general person/object recognition and model self-training
remain goals to demonstrate through outcomes, not assumptions from the architecture.
