| Stage | What Java checks |
| --- | --- |
| Review | The chosen course comes from the installed original content. Pin the manifest, hazard IDs and installed game-engine identities before approval. |
| Playtest | Run normal, steady and careful paces in isolated native sessions. Reopen each one in a fresh session. Require the original rail IDs, positive measured clearance and physical finish contact in the simulation. |
| Handoff | Save an ordered approval and handoff in the parent journal. Recheck the game's original procedure, exact source, replay evidence and report ID, version and contents before a dashboard can exist. |
| Dashboard | Generate a stable report from the original crossing values. Use actual Chromium checks on every row, each pace filter and the export link. Retain an exact source receipt and full-precision CSV. |
| Recovery | Resume from the approved playtest boundary after hard process termination. Check both courses and a revised artifact on each side. Verify History with the same original evidence and reopen the prior ramp chain. |
