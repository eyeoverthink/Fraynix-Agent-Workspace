## Implementation

- Java checks calibration coverage against normalized scene geometry, target
  roles, force/torque, gravity and existing distance. Changed fixed obstacles or
  a substantially different starting arrangement do not inherit old savings.
- A bounded monitor reads at most three eligible completed memory outcomes for
  the selected receipt, workload, proof state and nearby scene. Only outcomes
  newer than the calibration, with current implementation/resource identity,
  qualify. Original jobs, native traces, commits and timing must verify.
- Compare each measured memory duration with the existing estimate for that
  task. The empirical tolerance is max(1000 ms, 20% of predicted memory cost,
  the retained savings margin). Two same-direction deviations in those three
  observations mark the estimate suspect. This is a drift warning, not a
  confidence probability or evidence about the unobserved alternative.
- Calibrated selection uses simple control on missing scene coverage or suspect
  costs. Forced simple/memory controls remain unchanged. Freeze the exact prior
  observations and proof hashes into each decision and recheck them on audit;
  restart must preserve the decision. A new independently verified fit is the
  way to replace a suspect model; no invented costs or automatic weight training.
- Keep scan/verification overhead inside the complete goal timer. Surface the
  reason and source outcomes in the existing report, without new app windows.
