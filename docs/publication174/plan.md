# Edition 174 implementation and acceptance gates

The local registry offers a single-setup experiment and a paired comparison. Both read an exact Chromium source revision and require real native and canvas checks. The single procedure produces one trajectory. The comparison requires two setups with the same duration and independently verifies both trajectories on a common clock.

| Gate | Required evidence |
| --- | --- |
| Select a procedure | Verify raw local-model proposals on previously unseen wording. Count clarification as its own outcome. |
| Bind the data | Retain the actual original CSV bytes and both observed tables. An available single setup does not satisfy a comparison request. |
| Execute and replay | Require four distinct Bullet sessions for the paired procedure, two per setup. Check sample cadence, position, velocity, rotation, travel and contacts in both pairs. |
| Verify the output | Recompute the signed distance difference and confirm the live chart switch, measurements and source links. |
| Recover | Stop the Java process with the report retained and verify after reopening. Reopen a report produced by the earlier contract. |

## Next implementation

Collect a larger, balanced request set across physics, data and creation. Include requests with ambiguous results, missing sources and copied text from untrusted pages. Measure routing accuracy and verification cost against direct dispatch. Prefer a direct registered command when it captures the request completely. Require clarification before execution when the desired result or a necessary source is missing.
