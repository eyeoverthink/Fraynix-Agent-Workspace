# Edition 173 implementation and next gates

The ramp experiment now has one registered contract covering input, native execution and report verification. The existing form and an imported CSV become versioned local Chromium pages. Java checks the browser rows, runs the same Bullet procedure and applies the same receipt checks.

| Stage | Input | Output |
| --- | --- | --- |
| Browser | Exact local source revision | Verified browser rows |
| Experiment | Those measured input rows | Native motion trace |
| Replay | Original trace and bound engine | Fresh replay comparison |
| Report | Verified comparison | Versioned HTML, CSV and JSON |
| Canvas | Saved report revision | Real checks against the rendered artifact |

The direct request and the opt-in local model use identical source bindings and the same typed admission rules. The model can select the registered procedure. Java keeps the user's pause setting and owns execution, recovery and the result. CSV imports keep their original UTF-8 bytes, including the byte-order mark and line endings when present.

## Next implementation

Register a second experiment with meaningfully different semantics, such as comparing two ramp configurations on a common clock. Expose both admissible procedures in the same local catalog. Evaluate when a local model selects the right one from ordinary wording, when it should ask for missing inputs, and when direct routing is faster. Require independent outcome checks, interrupted execution tests and preserved original receipts in every route. Measure usability at the point where the user supplies inputs and reads the result.
