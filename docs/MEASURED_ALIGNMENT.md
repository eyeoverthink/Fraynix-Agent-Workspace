# Measured mat/native alignment and manual physical trials

Open **Spatial → Measured mat alignment** after linking a persistent native world. The camera, reference calibration, target template and trial recorder are explicit controls. Java owns the transformation, source checks, target observations, motion estimates, phase windows and evaluation. The existing native bodies are read, not moved.

Start the top-down camera and freeze a fresh frame. Select four known printed-grid corners in perimeter order: origin, across, opposite, up. Enter their measured width and height. Add at least three other known grid intersections as withheld checks; specify their distances across/up from the chosen origin. These points must be distinct from fitting/calibration corners. Select two independent tape marks and declare their units. Draw the current target and a background/distractor example such as the tape housing.

The default native placement sets the mat origin to `[0,0,0]`, its across direction to `+X` and its upward-on-mat direction to `−Z`. Advanced controls accept a different explicit orthonormal basis/origin. This placement defines where the measured plane belongs in the virtual scene. It is not a measured pose in a physical room. The planar similarity fit estimates rotation, translation and scale inside that basis. It preserves handedness; malformed/degenerate references are refused.

Registration passes only when fit RMS ≤3 mm, maximum withheld-point residual ≤5 mm, independent tape-length discrepancy ≤5 mm, and fitted scale lies within0.98–1.02. Near-zero error on reused fitting corners is expected by construction. It is not an accuracy result. The declared3 mm annotation budget and unmodelled height/parallax still apply. A failed check is retained as its own immutable registration; another annotation/version is a new record.

The new target matcher uses an immutable human-selected colour/edge template, fixed background exemplars, mat-constrained search and bounded recovery. No target template updates occur during a scored trial. Score, ambiguity and negative-example margins describe matching, not semantic identity or probabilities. The original038 matcher/filter/results remain separate. The current motion filter predicts two planar axes in actual host acquisition seconds; its radius is an uncalibrated model budget.

## Manual workflow

For a tape movement, leave the lighter uncovered. Align the same metal end at the declared start mark, take your hand away and begin. The recorder saves exactly eight post-seed start samples and pauses. Click **Start moving**, slide the same end to the declared end mark, release it and take your hand away. Click **At end mark; hand away**. The next eight frames are the fixed endpoint window. The app pauses again; finish the recording. There is no deadline to perform the move or click between holds. Keep orientation approximately parallel.

For occlusion, begin with the lighter visible and hand away. After eight start frames, cover only the lighter without hiding the reference corners. Click **It is covered** after the cover is in place. The recorder saves eight hidden frames and pauses. Uncover the lighter, remove your hand, then click **Visible again; hand away**. It saves eight revealed frames and pauses. Finish the recording. A stationary control saves twelve post-seed frames and pauses.

The first designated windows are fixed. The recorder does not wait for favourable later measurements, drop failed endpoint frames or silently extend a hold. Movement requires every start/end frame to be measured; its vector error must be ≤10 mm relative to the independently declared tape displacement. Occlusion requires zero accepted target measurements during the eight hidden frames, at least80% measured recovery in the eight revealed frames, and return error ≤10 mm. A stationary control requires all twelve measurements and RMS jitter ≤3 mm. Jitter is not absolute accuracy.

Completing capture does not pass a physical test. Independent reference annotations must identify the exact original-frame hashes and actual visibility. Movement additionally requires confirmation of the same physical end at the declared marks. If the target stayed visible during a nominal hidden phase, or visibility/mark alignment cannot be corroborated, the result remains unscored. The first evaluation is immutable. Predictions are never ground-truth references. The contract is in [alignment-041-contract.json](../workspace-engine/src/main/resources/alignment-041-contract.json), with [candidate source lock](ALIGNMENT_041_CANDIDATE_LOCK.json) and [first reference-annotation lock](ALIGNMENT_041_FIRST_ANNOTATIONS_LOCK.json).

## Source integrity, display and files

Each original is privately saved before observation with its SHA-256, ordinal, phase and actual host-monotonic ImageCapture completion seconds. These are not certified sensor exposure timestamps. Uploads are single-flight, scheduled at most 5 Hz. Actual first-hold acquisition intervals averaged about 1.46 seconds; the ceiling is not achieved throughput. Limits are300 post-seed frames and32 MB of committed originals per trial; a pending original is preserved if its commit fails. Original bytes/time/phase require exact replay. Late generations, changed camera keys and stale native ownership/revisions are refused. App restart retains interrupted prefixes and first results; it never silently resumes a camera session.

The mat/camera reference guard checks the source grid patches on every sample. Reference failure suspends registered measurement. A current native head is required before capture; a changed head is shown as stale rather than rebased. Registered markers appear in the existing Java perspective/top/front/side projections. Their small visual size and offset are diagnostic choices. The surface point is mapped, while object height and contact remain unknown. Native entities, poses and clocks stay exact.

`alignment.read` pins the selected registration/trial evidence for local chat. `alignment.report` opens its real numeric report and checks the exact snapshot, registration, trial, landmark-row count and four Java views in the actual canvas. Model tools accept no supplied measurement, source identity, reference label, camera command or success flag. A verified report workflow can correctly contain a failed or unscored physical trial.

Reports contain actual residuals, sampled motion, CSV, source-qualified view JSON and a complete compressed numeric snapshot. They contain no personal camera pixels. **Export numeric JSON** writes a real local file; [Inspect-Alignment041.cjs](../scripts/Inspect-Alignment041.cjs) independently verifies its canonical hashes, registration/source relationships and increasing frame sequence. The original images remain in the private project’s `alignment-041/frames` directory, outside Git. The application does not include raw private frames in agent model prompts or external research requests; development review separately inspects private originals. Publication uses numeric-only views or labelled controls.

Keep the current live app’s installed JARs intact. Development and heavy validation run in separate source checkouts and distinct projects. Use CPU-only agent planning after the earlier unexplained Windows shutdown; do not overlap heavy native/model checks with physical capture. Preserve all original038 failures, previous projects and numbered README snapshots.
