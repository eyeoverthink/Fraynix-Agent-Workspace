# Edition 172 implementation and next gates

The first useful cross-domain path is a bounded mechanical experiment. A local browser page provides the input. The Java task binds the original revision, checks what Chromium reads, runs Bullet in a separate simulation and repeats it. The creation canvas verifies the report with real clicks before Java marks the task complete.

| Stage | Authority and check | Recovery |
| --- | --- | --- |
| Browser | The Chromium DOM must show the five expected typed rows from the admitted local artifact revision. Java independently loads the source JSON and regenerates the expected page. | Keep the accepted observation. A changed current revision stops unfinished work. |
| World | Java uses the accepted browser values to construct a bounded ramp. Fresh native replay must match the original sampled motion and contact counts within the declared gates. | Keep completed trial receipts. Recreate a trial only if it never reached a saved checkpoint. |
| Canvas | Java writes one idempotent, versioned artifact. Chromium verifies the visible result, row count, evidence links, and replay toggle. Java compares that receipt with the frozen checks. | Recover the existing report and require the outstanding checks. Completed and archived work can reopen its original report. |
